## 2024-06-10 - Unbounded Local Data Input Resource Exhaustion
**Vulnerability:** CoreData/SwiftData entities allowed unbounded text inputs (title, notes) and unvalidated image sizes, causing UI rendering freezes and potential JetSam memory crashes when excessively large strings or 100MB+ images were loaded into SwiftUI view states.
**Learning:** Even entirely local, offline apps require strict input bounds. Local persistence frameworks can be easily DOSed by the user (or via synced external data) if arbitrary sizes are allowed to serialize into the main context or views.
**Prevention:** Always enforce logical limits directly on SwiftUI text fields using `.onChange` text truncation, strictly limit unbounded arrays (like steps), and validate `Data` object sizes before persisting them.

### 2026-06-13 - Format String Crash in SwiftUI Text LocalizedStringKey Evaluation
- **Vulnerability**: The application was passing user-controlled input (`task.notes`) directly into `Text(.init(_:))`, which implicitly resolves to `Text(_: LocalizedStringKey)`. If the input contains string format specifiers like `"%@"`, SwiftUI attempts to resolve these arguments. Because no arguments are provided, this causes a runtime crash, allowing for a trivial Denial of Service (DoS) attack.
- **Learning**: Explicitly instantiating a `LocalizedStringKey` (e.g. via `Text(.init(...))` or `Text(LocalizedStringKey(...))`) with unvalidated or arbitrary user input creates a format string vulnerability in SwiftUI. This mechanism is frequently misused by developers seeking automatic Markdown or localized link parsing.
- **Prevention**: To safely parse Markdown and extract clickable links from user input without evaluating it as a `LocalizedStringKey`, use `AttributedString(markdown:)` within a `try?` block and pass the resulting attributed string to `Text()`. If parsing fails, fall back to plain `Text(task.notes)` or `Text(verbatim: task.notes)` to ensure user input is treated strictly as plain text.
